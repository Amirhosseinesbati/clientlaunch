# Implementation status — 2026-09-28

ClientLaunch is an independent synthetic portfolio pilot. The local Docker launch, signed intake/replay, exact user-authorized approval, forced partial board failure, operator recovery and a five-answer client submission have been exercised through n8n. **Runtime acceptance remains incomplete** for the logo asset, handoff, scheduled retry/reminder behavior, connected providers and full restore.

## Completed and locally verified

- FastAPI business API, AI-only LangGraph planning service, React operator/client views, ten n8n workflow exports (**current source: 96 nodes**), Compose configuration, migration/seed scripts, dependency lockfiles and documentation are present. The latest source includes frozen purchased-service folder blueprints, child-folder provisioning, an authenticated reminder-run webhook, task-card reconciliation, handoff detail, connected-startup guards and a five-minute pending-dispatch sweep.
- The full synthetic seed completed against PostgreSQL: 2 workspaces, 60 clients, 90 won deals, 8 service types / 16 template rows, 1,000 checklist rows, 250 assets, 180 submissions, 649 task cards and 30 planted partial-failure histories. The same migration and seed were also exercised locally with SQLite.
- The one-command Docker launch brought up PostgreSQL, n8n, the API, AI service and web app, and applied migration `0003`. Docker Desktop briefly went offline, then recovered. A **94-node** pack was reimported/published as ten workflows with five webhook routes; API and n8n health returned HTTP 200 after recovery. DEMO reminder and dispatch schedules were active, though scheduled behavior remains unverified. The later 96-node export has **not** been reimported because Docker overlayfs returned an I/O error.
- A signed synthetic won-deal event traversed the n8n webhook and returned HTTP 200. Replaying the identical event returned HTTP 200 with the same onboarding; changing its scope under the same event ID returned HTTP 409. At least 15 n8n execution records were observed, including successful runs and one error from before the workflow fix. This evidence establishes the intake/replay path, not the whole onboarding journey.
- Local checks reported **17 API tests** (including five isolated connected-startup guard tests and targeted viewer/card/board regressions), 6 AI tests, 3 web tests, frontend typecheck and a production Vite build after the latest UI change, 10-workflow/96-node static validation and `docker compose config --quiet` passing. `compose.yaml` now passes `APP_MODE`, `COOKIE_SECURE` and `CORS_ORIGINS` into the API, and `.env.example` declares them; the new connected configuration has not run in Docker. GitHub Actions CI has not run.
- The user-authorized Willow Harbor Studio DEMO plan was approved exactly once. A one-shot simulated Trello board failure occurred after successful root and seven child folder creation. Operator recovery retried the board operation, reused the completed folders, then produced one board, six cards and one welcome outbox entry. The onboarding reached `waiting_for_client`; nine provisioning operations succeeded, none remained failed. n8n recovery/provision/board/task-sync executions 37–40 succeeded. Earlier no-op recovery/task-sync webhooks also completed on an unprovisioned demo onboarding. `pg_dump`/`pg_restore` smoke tests of both PostgreSQL databases succeeded in isolated temporary databases with matching record counts before migration `0003` and the tenth workflow import; no restored service or asset volume was started.
